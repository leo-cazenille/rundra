# M12.2 - Docker Slurm cgroup validation

## Goal

Add an opt-in Docker system test that proves Slurm enforces a Task's memory
limit. Keep the existing rootless Rundra end-to-end harness as the portable
default and do not add the privileged test to normal CI.

## Design

1. Extend the existing Docker Slurm image with `stress-ng` in a separately
   tagged test layer.
2. Run one compute container with a private, writable cgroup-v2 namespace and
   Slurm's `task/cgroup` and `proctrack/cgroup` plugins enabled.
3. Preflight cgroup v2, the memory controller, and delegated cgroup write
   access before starting the cluster.
4. Submit a small successful control job followed by a 64 MiB job that tries
   to retain 512 MiB. Require Slurm to report `OUT_OF_MEMORY` and require the
   workload's success marker to remain absent.
5. Preserve Compose logs and Slurm state on failure. Document this test as a
   privileged, development-only check rather than a production deployment
   recipe.

## Acceptance criteria

- `tools/run_docker_slurm_cgroup_tests.sh` passes on a compatible Docker host.
- The ordinary Docker Slurm test remains rootless and unchanged.
- Unsupported hosts fail before cluster startup with an actionable cgroup
  capability message.
- The cgroup variant is manually invoked and is not part of default pytest or
  scheduled CI.
