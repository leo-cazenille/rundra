# M10.2 - Shared Results and Scalable Retrieval

## Goal

Make retrieval efficient for large runs, especially when the client and target
workspace are on the same shared filesystem. Preserve the existing copied-file
workflow while adding immutable references, lane-level result archives, and
archive-aware analysis.

## Increment 1: shared-filesystem staging and retrieval

- Add an explicit `shared` staging backend with a configured absolute root.
- Require source, workspace, and destination paths used by this backend to stay
  beneath that root after symlink resolution.
- Stage through local filesystem operations rather than routing shared data
  through SSH and rsync.
- Keep existing target configuration versions and staging backends unchanged.

## Increment 2: immutable reference retrieval

- Add `auto`, `copy`, `reference`, and `archive` fetch modes.
- Make `auto` select a constant-time reference manifest for shared targets.
- Write reference manifests atomically and include the run, output, metadata,
  log, and selected-pattern locations.
- Permit references only for terminal runs, whose runtime output namespace is
  immutable by framework contract.

## Increment 3: lane-level result shards

- Seal each Slurm worker lane's task output directories into one deterministic
  tar archive on the allocated compute node.
- Publish each archive and checksum atomically, then remove the archived loose
  task directories.
- Include a machine-readable member index with task statuses, sizes, and
  SHA-256 hashes so partial lane results remain independently usable.
- Record shard availability in scheduler metadata and fetch shard files instead
  of unavailable loose task directories.

## Increment 4: archive-aware fetch and analysis

- Add optional safe extraction after fetch.
- Validate archive paths, sizes, and hashes before publication of extracted
  files.
- Allow Pogosim analysis to consume a copied directory, a shared reference
  manifest, or result shards directly without transient extraction.

## Increment 5: compact human output

- Summarize large task/seed collections in human-readable submit, status, and
  fetch output.
- Preserve complete task data in documented JSON output.

## Compatibility and validation

- Introduce a new target configuration version for `shared`; versions 1-4 keep
  their existing parsing and behavior.
- Keep copied retrieval as the behavior of existing local and rsync targets.
- Add focused unit and fake-backend integration tests for each increment.
- Run the complete test, lint, formatting, type-checking, and local execution
  validation before declaring the milestone complete.
